# PRD — N.O.V.A. 2026 Doctor Agent

> 상태: **초안 (v0.1, 10.10)** · 참가자 가이드 수신 후 v0.2로 갱신
> 착수: **10.12 (예선 시작일)**

---

## 1. 목표

가상 환자를 문진·진찰하고 **S·O·A·P 초진 기록 + 주진단 1개**를 제출하는 Doctor Agent를 만든다.

- **예선 목표:** 고정 모델(gpt-oss-20b) 위에서 *설계*로 차별화 → 본선 진출
- **본선 목표:** 예선 파이프라인과 로그를 그대로 재사용해 파인튜닝 모델로 교체

### 예선 채점 (증례당 100점)

| 영역 | 배점 | 보는 것 | 우리 대응 |
|---|---|---|---|
| 정보수집 | 25 | 필요한 문진·진찰을 **실제로 하고 기록**했는가 | 주호소별 필수 체크리스트 + 로그 기반 SOAP |
| 효율 | 20 | 불필요한 행동·**모델 사용 비용**을 줄였는가 | 턴 예산, LLM 호출 4~6회 상한 |
| 진단추론 | 15 | 주진단 정확도, 근거·감별진단 타당성 | 감별진단 상태 유지, Replan |
| 안전 | 15 | 처치가 적절하고 해롭지 않은가 | red-flag 규칙 레이어 |
| 의사소통 | 15 | 소통하고 필요한 설명을 했는가 | 마무리 SAY(진단 설명·교육·재방문 기준) |
| 검사·추적 | 10 | 필요한 검사·추적 계획 | P 항목 템플릿 |

**SOAP 작성 원칙 (개회식):** 묻거나 진찰하지 않고 적은 내용은 인정되지 않는다. O의 진찰 소견에는 **결과를 받은 턴 번호**를 적는다. 교육은 계획에 적는 것과 별개로 진료 중 SAY로 실제 설명해야 한다.

## 3. 핵심 결정

| # | 결정 | 근거 |
|---|---|---|
| D1 | **자체 평가 벤치를 만든다.** 증례 = AgentClinic-MedQA 번역 + Claude로 합성한 한국어 외래 증례 ~100개. 환자 = 로컬 gpt-oss-20b, 채점 = 대회 크레딧의 채점용 GPT(6영역 루브릭). 채점 호출은 1회 벤치 = 30증례로 제한. MIMIC·MedDialog는 제외(접근 절차·시간). | 샘플 증례는 소수일 것 → 과적합 방지. 리더보드는 5증례라 노이즈 큼 |
| D2 | **턴 예산: 목표 15~25, 상한 35.** 설정값으로 두고 15/20/25/30 스윕. | 정보수집 25 > 효율 20. 극단적 단축은 손해 |
| D3 | **Plan → Execute → Replan. LLM은 계획·상태 갱신만, 행동 선택은 코드.** 감별진단 확률은 Replan 시점에만 갱신. 정지 조건 = (1위−2위 확률 ≥ θ) AND 필수 체크리스트 충족, 또는 예산 소진. | 매 턴 LLM 호출 시 30회+ → 효율 감점. 20b에 행동을 통째로 맡기면 반복·이탈 |
| D4 | **안전 레이어 = 주호소별 red-flag YAML.** 필수 문진·진찰·배제 질환을 정의(초기 15개 주호소). 마무리에 응급 징후·재방문 기준을 SAY로 말하고 P에도 기록. | 안전 15 + 의사소통 15를 규칙으로 안정 확보 |
| D5 | **Self-consistency 기본 OFF.** 예외: 최종 진단 3회 다수결은 벤치에서 이득 확인 시에만. 컨텍스트에는 대화 전체가 아니라 **구조화 상태표**(증상·소견·턴 번호)만 넣는다. | 모델 비용 = 효율 점수. 컨텍스트 오염·길이 제한 방지 |
| D6 | **제출 운영: 10.12 베이스라인 → 이후 1일 1변경.** 채택 판단은 로컬 벤치 기준, 서버 점수는 회귀 확인용. 마지막 2일은 안정화. | 서버 제출 총 11회뿐, 리더보드 5증례 |
| D7 | **본선 대비: LLM 클라이언트 추상화 + 전체 실행 로그(JSONL) 저장.** 본선 베이스 모델은 Qwen3-14B 계열로 잠정(예선 후 확정), MedExAgent 레시피(SFT → RL, 비용 패널티) 참고. | 예선 로그 = 본선 학습 데이터·발표 자료 |

## 4. 아키텍처

```
[시작] 환자 첫마디 + 활력징후
   │
   ▼
① PLAN (LLM)      감별진단 3~5개 + 구별용 질문/진찰 계획(JSON)
   │              + red-flag YAML에서 필수 항목 병합
   ▼
② EXECUTE (코드)  계획을 1턴씩 실행 → 응답을 상태표에 [턴, 행동, 응답]으로 기록
   │              SAY 30자/질문 1개 검증, EXAM 1개 검증, 중복 질문 제거
   ▼
③ REPLAN (LLM)    상태표로 감별진단 확률 갱신 → 정지 조건 판정
   │   ├─ 미충족 → 추가 계획 → ②
   │   └─ 충족   → ④
   ▼
④ CLOSING (SAY)   진단 설명 · 주의사항 · 응급 징후 · 재방문 기준 (1~2턴)
   ▼
⑤ SOAP (LLM)      상태표에 있는 사실만 사용, O에 턴 번호, A에 근거·감별, P 템플릿
   ▼
⑥ VALIDATE (코드) 근거 없는 항목 제거, 필수 섹션 확인 → DIAGNOSE

가드: 경과 15분 또는 남은 턴 ≤ 3 → 즉시 ⑤로 이동
      LLM 호출 실패 → 재시도 1회 후 규칙 기반 SOAP로 폴백 (단, 증례당 정상 호출 1회는 반드시 보장)
```

## 7. 실험 원칙

- 모든 변경은 **로컬 벤치 점수(영역별)**와 함께 기록한다.
- 서버 제출은 하루 1회, **변경 1개씩** — 점수 변화를 그 변경에 귀속시킨다.
- 벤치 실행 로그(JSONL)는 전부 보관한다 → 본선 학습 데이터.
- 합성 증례의 생성 코드·프롬프트도 커밋한다(재현성 요구).
- 크레딧 사용량을 매일 확인한다(채점용 GPT 호출이 주 비용).
